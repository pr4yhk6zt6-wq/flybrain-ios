ตรวจแล้วพบว่ากฎเดียวกันถูกเขียนไว้ 3 ที่ และ **ไม่ตรงกันที่หนึ่งค่า**:

ทั้งที่คอมเมนต์อ้างถึงข้อ #11 ซึ่งบอกว่า 1.0

เกี่ยวกับ *เครื่องมือ* ไม่ใช่เกี่ยวกับ *สัตว์* ต้องวัดใหม่ที่ κ=1.0

- fail ถ้ากฎของออร์แกนเลิกใช้ κ ที่ *มีชื่อ* (บั๊กนี้คือการใช้ literal)

## 6. รอบที่ 2 — จากภาพหน้าจอ `IMG_2714` (v0.6 ติดตั้งสำเร็จแล้ว)

**ข่าวดี**: v0.6 อยู่บนเครื่องจริง ๆ แล้ว และ **ไม่มีวีดีโอวิ้ง ๆ อีก** — สัตว์ยืนบนพื้น
`feet 6/6 · COM z −0.0234 cm · 6 contacts` กับ `cord 614 updates` พิสูจน์ว่า solver รันบนเครื่อง

### บั๊กที่ HUD ในภาพนี้เปิดเผย (แก้แล้ว)

`0/42 pools · 0.0 Hz · desc 0.0 Hz (tone 2.5) · organs 0.0 Hz`
`over 4569 ms · net 212543 spk/s · groups 114/42622 · spikes 393 (pools 15)`

อ่านสองบรรทัดนี้ด้วยกัน = **คำตอบที่ CI หาไม่ได้มาตลอด**: ตัวเลข `spikes 393 (pools 15)`
เป็นตัวนับที่ **GPU เขียนเอง** → pool ยิงจริง (ประมาณ 10–40 Hz) แต่ทุกอัตราที่แอปอ่านได้เป็น 0.0 Hz

สาเหตุ (เจอจากการไล่โค้ด ไม่ใช่จากการเดา): `FlyCord.source` เป็น **`weak`** และหน้าจอ Body สร้าง
source เป็น **ตัวแปรท้องถิ่น** (`WorldView.attachCord`) ที่ไม่มีใครถือไว้ → ARC ปล่อยทิ้งทันทีที่
ฟังก์ชัน return ทุก `source?…` จึงกลายเป็น no-op ตลอดชีวิตของแมลง: tone ไม่เคยไปถึง descending,
organ ไม่เคยถูกขับ, และทุก rate อ่านได้ 0 Hz — `tone 2.5` ที่โชว์คือค่าที่ cord *ตั้งใจจะส่ง*

* แก้: cord **ถือ source แข็ง** และสร้างโดยไม่มี source ไม่ได้ (ชนิดข้อมูลบังคับ)
* ด่านกันซ้ำ: `testTheCordOwnsTheRateSourceItReadsFrom` สร้าง cord แบบเดียวกับแอป **แล้วพิสูจน์แล้ว**
  ว่าจับบั๊กได้จริง — เอา `weak` กลับไปใส่ = เทสต์ **fail** (ข้อความตรงกับที่เขียนไว้), ใส่ตัวแก้ = ผ่าน
* เทสต์เดิมทั้งชุดมองไม่เห็นบั๊กนี้ เพราะในเทสต์ stub อยู่ในตัวแปรที่อายุยืนเท่าฟังก์ชันเทสต์

### กล้อง — บั๊กจริง 2 ข้อ (แก้แล้ว)

1. **หมุนไม่หยุดเพราะท่า gesture ผิด**: `DragGesture.translation` คือระยะ *สะสมตั้งแต่เริ่มลาก*
   แต่โค้ดเดิมเอาไป **บวกซ้ำทุก event** (60–120 event/วินาที) → การหมุนโตแบบยกกำลังสอง
   ลาก 200 pt ผ่าน 100 event ≈ 80 เรเดียน (สิบกว่าตลับ) ตรงกับที่คุณบอกว่า "หมุนเร็วมาก"
   → แก้เป็นใช้ **ผลต่างระหว่าง event** + ลดความไว (0.0035 rad/pt) + จำกัดมุมเงย ±1.45
2. **ซูมเข้าไปอยู่ "ในตัวแมลง"**: เพดานใกล้สุดเดิม 0.06 cm แต่ลำตัวยาว 0.297 cm → กล้องเข้าไปในทรวงอก
   เห็นแต่ผิวด้านในที่ถูก near-plane ตัด → ดูเหมือน "โมเดลพัง" ทั้งที่โมเดลไม่พัง
   (หลักฐานในภาพของคุณเอง: หน้าต่าง left eye / right eye ซึ่งกล้องอยู่ที่ 0.30 cm เห็นแมลงครบตัวปกติ)
   → เพดานใกล้สุดใหม่ 0.22 cm + ปุ่ม **reset view** (ลูกศรย้อนกลับ มุมขวาบน) กลับไปมุมที่เห็นทั้งตัว

### สิ่งที่ควรเห็นในบิลด์ v0.7 (7)

* บรรทัด cord จะ **ไม่เป็น 0.0 Hz อีก** — ควรเห็น `N/42 pools` และ `desc ~50 Hz`
* สัตว์จะ **เริ่ม bouge** ตามที่วัดไว้ใน `reports/item4_walking.md` §4: COM จะจมลง (ประมาณ −0.035 cm)
  และขาจะรับน้ำหนักไม่เท่ากัน — **นี่คือผลที่วัดไว้ล่วงหน้าแล้ว ไม่ใช่บั๊กใหม่** และเป็นงานของข้อ 4 ต่อไป
* ถ้ายังไม่เห็นตัวเลข pool ขยับ → ส่งภาพบรรทัด `over … ms · …` มาอีกครั้ง

### หมายเหตุเล็ก ๆ จากภาพ

* แบตเตอรี่เหลือง = **Low Power Mode** ซึ่ง throttle GPU/CPU → ตัวเลข `0.03× real time` (ฟิสิกส์)
  และ `0.06× real time` (คอร์ด) อาจดีขึ้นถ้าปิดโหมดนี้ ลองปิดแล้วดูตัวเลข RTF อีกครั้ง

2. **แพ็กด้วย `zip -r`** → เปลี่ยนเป็น **`ditto -c -k --sequesterRsrc --keepParent`** (เครื่องมือของ Apple)
   เพื่อรับประกันสิทธิ์ไฟล์ในซิป (สาเหตุคลาสสิกของค้างที่ติดตั้ง)

คีย์ plist, ไฟล์ข้อมูล, ห้าม `frames.bin`, **ห้ามไฟล์ซ้ำเกิน 64 KB**, และเลขเวอร์ชันต้องตรงกับ `project.yml`
